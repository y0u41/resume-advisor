# 错误码目录（error-codes）

> 权威实现：`server/http/errors.js`。`code == 0` 表示成功。
> 响应统一信封（见 `server/http/envelope.js`）：
> - 成功：`{ "code": 0, "message": "ok", "requestId": "...", ...原字段 }`
> - 失败：`{ "code": 2001, "message": "账号或密码错误", "requestId": "...", "error": "账号或密码错误", ...原字段 }`
>
> 兼容说明：为平滑迁移，响应同时保留原有字段（失败保留 `error`），旧前端无需改动。

## 通用

| code | 含义 | 常见 HTTP |
|------|------|-----------|
| 0 | ok | 200 / 201 |
| 1001 | 参数错误 / 校验失败 | 400 / 422 |
| 1002 | 未认证 | 401 |
| 1003 | 无权限 | 403 |
| 1004 | 资源不存在 | 404 |
| 1005 | 冲突（并发） | 409 |
| 1006 | 内容过长 | 400 |
| 1007 | 请求过于频繁 | 429 |

## 认证

| code | 含义 |
|------|------|
| 2001 | 账号或密码错误 |
| 2002 | 邮箱已注册 |
| 2003 | 注册已关闭 |

## 额度

| code | 含义 |
|------|------|
| 3001 | 额度已用完 |

## LLM

| code | 含义 |
|------|------|
| 4001 | LLM 调用失败 |
| 4002 | LLM 配置错误 |

## 文件

| code | 含义 |
|------|------|
| 5001 | 文件解析失败 |
| 5002 | 不支持的文件格式 |
| 5003 | 文件过大 |
| 5004 | 无法提取文字 |

## 链接

| code | 含义 |
|------|------|
| 6001 | 链接抓取失败 |
| 6002 | 不允许的来源（SSRF 防护） |

## 用户

| code | 含义 |
|------|------|
| 7001 | 用户不存在 |

## 兜底

| code | 含义 |
|------|------|
| 9001 | 服务端内部错误 |

## 约定

- 请求 ID：每个响应带 `X-Request-Id` 响应头与 `requestId` 字段，便于日志追踪。
- 接口可显式返回 `code` 覆盖默认映射（例如注册重复返回 `{ code: 2002, error: "邮箱已注册" }`）。
- SSE 流式接口（`/api/evaluate?stream=true` 等）不使用信封，错误以 `data: { "error": ... }` 事件下发。
