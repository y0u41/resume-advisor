# 需求研究（Research）

> 项目：简历参谋（resume-evaluator）
> 整理日期：2026-09-11 ｜ 对应实现：2026-09-10

## 1. 项目背景

求职季中，简历是求职者与招聘方之间的第一道门槛。一份简历是否契合目标岗位，直接决定能否拿到面试机会。然而现实是：

- 大多数人不知道自己的简历"差在哪"，只会反复海投却收不到回音；
- 招聘 JD（岗位描述）里写满了要求，但求职者很少逐条对照，判断"我到底匹不匹配"；
- 能提供专业简历辅导的人（学长、老师、付费机构）稀缺、昂贵、且反馈不及时。

大模型的出现，使"把简历 + JD 交给 AI，得到一份结构化、可执行的诊断报告"成为可能。本项目即围绕这一机会点立项。

## 2. 目标用户

| 用户类型 | 占比预期 | 特征与诉求 |
|----------|----------|------------|
| **应届生 / 在校生** | 主力 | 无正式工作经历，容易被"经验年限"类要求劝退；需要按"应届生标准"评估，重点看项目、实习、竞赛、潜力 |
| **1–3 年职场新人** | 次主力 | 转岗 / 跳槽，需要针对具体 JD 打磨简历 |
| **泛求职者** | 长尾 | 想自查简历质量、做面试准备、生成规范简历 |

## 3. 用户痛点

1. **不知道问题在哪**：简历被拒，但拿不到任何反馈，无法定位短板。
2. **不会逐条对照 JD**：不清楚岗位要求与自身经历的匹配缺口。
3. **缺少可执行的修改方法**：只被告知"要改"，却不知道"怎么改"。
4. **简历格式不专业**：排版混乱、缺少关键词，过不了 ATS（简历筛选系统）。
5. **全流程割裂**：评估、改简历、投递、面试准备分散在不同工具里。
6. **隐私顾虑**：简历含姓名、电话、邮箱等敏感信息，用户担心被滥用。

## 4. 竞品与现有方案

| 方案 | 优点 | 不足 |
|------|------|------|
| **小析智能**（主要借鉴对象） | 落地页清晰、卖点突出、有隐私合规声明 | 以企业/机构为主，个人体验与"逐条对照 JD"不足 |
| 招聘平台内置简历诊断 | 入口方便 | 诊断浅、模板化、无针对性改法 |
| 付费简历优化服务 | 人工质量高 | 贵、慢、不透明 |
| 通用 AI 对话（ChatGPT 等） | 灵活 | 需要用户会提问；输出无结构；不做 JD 对照；无历史/闭环 |

**结论**：缺少一款"面向个人求职者、结构化输出、逐条对照 JD、覆盖求职全流程"的轻量工具。

## 5. 机会点与差异化定位

1. **结构化报告**：固定 9 个小节（总分、结论、岗位匹配对照、优点、问题清单、逐条改法、AI 修改建议、关键词补齐、增强方向），稳定可预期。
2. **逐条对照 JD**：用 ✅ / ⚠️ / ❌ 标注每一项要求，并计算匹配度，让"差在哪"一目了然。
3. **应届生模式**：不因缺少工作经历扣分，评估维度转向项目 / 实习 / 竞赛 / 潜力。
4. **全流程闭环**：没简历 → 评估 → 多岗对比 → 改简历 → 面试准备 → 岗位方向推荐。
5. **隐私合规**：独立隐私政策页，数据按用户隔离，密钥不入库，降低使用顾虑。

## 6. 关键洞察与设计原则

- **借鉴小析智能的落地页**：三大卖点 + 效果预览 + 隐私合规声明，把"登录页"做成"能说服人的落地页"。
- **黄金分割布局**：展示区 : 表单 ≈ 1.618 : 1；评分栏 : 明细 ≈ 1 : 1.618，追求视觉平衡。
- **降低门槛**：文件拖拽上传、一键试用示例、粘贴岗位链接自动提取要点。
- **成本可控**：默认使用免费模型（`*-flash`）兜底，同时支持付费旗舰模型。
- **可信度**：报告必须引用简历原话作为证据，严禁编造用户没写过的经历、数字或证书。

## 7. 需求验证方式

- 以 **MVP 快速上线**（先做"评估"单一闭环），再按迭代逐步补齐功能；
- 通过真实简历（含**图片型 / 扫描版 PDF**）实测，暴露并修复解析、白屏、崩溃等问题；
- 依据实际使用（自用 + 分享给朋友）持续调整功能优先级。

## 8. 结论

面向"应届生为主的个人求职者"，做一款**结构化、逐条对照 JD、覆盖求职全流程、且隐私友好**的简历评估工具，具备明确的需求空间与差异化价值。功能优先级围绕"评估 → 改简历 → 面试"主线展开。
