- **运行时**：Node 20 LTS + npm + pm2，代码置于 `/opt/git/resume-evaluator`，进程 `resume-evaluator`。
- **访问**：`http://<服务器公网IP>:3001`（未备案域名，80/443 暂不可用，走 3001 端口）。
- **环境变量**：配置 DeepSeek + 智谱 双 Key；`HOST=0.0.0.0`、`PORT=3001`、`CORS_ORIGINS`、`AUTH_SECRET`、`COOKIE_SECURE=false`、`DAILY_LIMIT=30`。
- **管理员**：通过 `npm run create-admin -- <用户名> <密码>` 创建（凭据不入库文档）。

### 部署中遇到的问题与修复

| 问题 | 现象 | 修复 |
|------|------|------|
| 生产白屏 | 页面空白，控制台 CSP / CORS 报错 | 内联主题脚本外置为 `public/theme-init.js`；CORS 中间件不再抛错；Vite 插件移除 `crossorigin` |
| 启动段错误 | `better-sqlite3` 相关 segfault | 从源码重装 `better-sqlite3`；解析库改为动态 `import()` 延迟加载 |
| 图片型 PDF 无法识别 | 只能提取 `-- 1 of 1 --`（12 字符） | 提取文字 < 20 字时判定为扫描版，渲染 PNG 后交视觉模型 OCR |
| GitHub 推送不稳 | `Connection was reset` | 网络恢复后重推；期间用打包 + 临时隧道让服务器直接下载更新 |
| 无 HTTPS | 浏览器提示"不安全" | 需域名 + ICP 备案，或改用香港服务器 |

## 5. 经验与教训

1. **原生依赖是部署的主要风险**：`better-sqlite3` 需编译，PDF/Word 解析库易在启动时崩溃 → 延迟加载 + 源码重装。
2. **CSP 与 `crossorigin` 会悄悄毁掉生产页**：本地正常、线上白屏，需专门回归。
3. **流式输出要有停滞超时与回退**，否则用户端会"卡死"。
4. **真实文件要尽早测**：图片型 PDF 在最后才暴露，说明测试样本要覆盖"扫描件/照片"。
5. **网络不可靠时要有替代通道**：GitHub 不通时，用打包 + 隧道直传服务器（后续改用 `codeload` 压缩包）。
6. **PDF 文字层顺序可能 ≠ 视觉顺序**：设计型排版（`z-index` / `position` / `transform`）会让标题被绘制到文末；解析需按坐标重建阅读顺序。
7. **推理模型会「想太多」**：思维链可能耗尽 `max_tokens` 使正文为空；结构化任务应关闭思考（`thinking: { type: "disabled" }`）。
8. **流式「成功但为空」必须当失败处理**：否则前端会误报「已生成」却无内容。
9. **重构要自动化 + 全量回归**：移动文件用脚本重算相对 import，再跑 `tsc` / 单测 / 验收。
