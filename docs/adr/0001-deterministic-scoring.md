# ADR-0001：确定性评分引擎，与 LLM 报告并存

## 背景

原实现完全依赖 LLM 生成评估报告：结果随机、不可解释、相同输入两次结果不同，也无法用于「客观分」的横向对比。

## 决策

移植 resume-workshop 的词典驱动算法到 `server/scoring/`：

- 关键词提取：`normalize` → 词典匹配（含别名）→ 英文专有名词兜底；权重 = 基础 + 位置加成 + 词频加成。
- 匹配度：`matchRate = Σ(weight × matched) / Σ(weight)`，拉丁词做词边界校验，可逐词解释。
- 四维评分：完整性 0.3 / 关键词覆盖 0.3 / 格式规范 0.2 / 量化成果 0.2；无 JD 时剔除关键词维度并重新归一化。
- 输出 `objective`，与 LLM 的 `report` **并存**，前端分开展示、互相印证。

## 后果

- 优点：确定性、可复现、可解释、零外部依赖、无需 LLM 即可出分。
- 代价：评分维度为启发式（面向纯文本简历做了适配），与 LLM 的语义判断可能不一致——这正是「互相印证」的意义。
- 不变量：相同输入必然相同输出；算法不发起网络请求。

## 更新（2026-09-12）：关键词来源支持 LLM，覆盖全行业

- 原内置词典偏技术岗，非技术岗（运营/市场/财务/HR/销售等）覆盖不足。
- 现改为：**关键词优先由 LLM 从 JD 抽取**（`server/llm/llm.js` 的 `extractJdKeywords`，按 JD 哈希缓存于 `server/core/jdKeywords.js` / `jd_keywords` 表），再走**原有的确定性匹配**（权重 = 基础 + 位置加成 + 词频加成）。
- 匹配与评分过程仍**确定、可解释**；只是「关键词来源」由内置词典扩展为 LLM。抽取失败时回退内置词典。
- 「算法不发起网络请求」的不变量相应调整为：**匹配算法本身不发起网络请求**，关键词抽取可选依赖 LLM。
- 前端在 AI 评分与算法客观分差异较大（≥20 分）时给出解释文案。
