# ADR-0007：报告保持文本格式，暂不做 JSON 结构化输出

## 背景

评估报告目前由模型输出**文本**（`【】` 分节 + `|` 匹配行），前端解析渲染。曾评估改用 `response_format: json_object` + JSON Schema，以提升「匹配对照条 / 评分徽章」的稳定性（即"专业感"）。

## 决策

**保持现有文本格式，不做全量 JSON 改造。**

## 理由（从用户使用角度）

1. **等待体验**：评估需 10~30s，现在是边生成边显示**可读中文报告**；改为 JSON 后等待期会显示原始 JSON，观感差（除非再加一层"隐藏原始流"，复杂度陡增）。
2. **内容质量**：JSON 模式常让模型输出**更短、更模板化**，牺牲「逐条改法 / AI 修改建议」这类最有价值的自然语言。
3. **成本与速度**：JSON 冗余字段更多 → token 更多、更慢。
4. **稳定性已有双保险**：
   - **确定性客观分**（算法）本身就是稳定、可复现的评分徽章；
   - 前端对文本格式已做**降级**：格式偏差退化为纯文本展示，不会崩。
5. **新增风险**：部分模型/网关的 JSON 模式偶发返回空或非法 JSON，反而更不稳。

## 量化触发器（解析降级率）

本决策**可基于事实重启**：把「报告格式偏差」从主观判断变成一个可观测指标。

- **指标定义**：`解析降级率 = report_parse_fallback / report_parse`（近 7 天滚动）。
  - `report_parse`：每次查看报告、调用 `parseReport` 时记一次（`src/pages/Result.tsx`）。
  - `report_parse_fallback`：`parseReport` 返回 0 个小节、退化为纯文本时额外记一次。
- **查看**：管理员 `GET /api/admin/parse-health`，或后台「报告解析健康度」卡片（含是否达标）。
- **触发条件（启用预留方案）**：`样本 ≥ 200` **且** `降级率 > 5%`。
  - 阈值可用环境变量覆盖：`PARSE_WINDOW_DAYS`(7) / `PARSE_DEGRADE_THRESHOLD`(0.05) / `PARSE_MIN_SAMPLES`(200)；改动需同步本 ADR。
- **达标后**：启用「尾部机器可读块」——保留 9 节可读文本，仅在**末尾追加一个精简块**（仅 `score` + 「岗位匹配对照」的结构化条目，如 `<!--RESUME_META {...}-->`）；前端**优先文本解析，失败才回退读它**。
- **复查与回退**：启用后若降级率降到 `< 1%` 并稳定 2 周，可移除机器可读块。

## 后果

- 报告继续使用文本格式（`server/llm/prompt.js` 的固定 9 节）。
- 埋点 `report_parse` / `report_parse_fallback` + `server/core/parseHealth.js` 已就位，决策不再靠"感觉"，而是看降级率是否越过上述阈值。
- 若越过阈值，按上文「触发条件」实现**小范围**的尾部机器可读块方案（而非全量 JSON）。
