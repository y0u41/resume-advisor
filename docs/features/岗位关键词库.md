# 岗位关键词库

> 把 `jd_keywords` 表当**数据资产**：它在评估过程中自然沉淀「各行业 JD 高频关键词」，
> 稍加清洗就是一个可公开的「岗位关键词库」页面 —— 既是 **SEO 获客入口**，也是竞品拿不走的积累。

## 概述

每次评估/游客试用时，服务端会用 LLM 从 JD 抽取关键词并按 JD 哈希缓存（`jd_keywords`）。
本功能把这些缓存**再聚合**成按岗位方向分类的高频关键词库，公开可访问、可被搜索引擎索引。

## 数据来源与沉淀

- 抽取入口：`server/core/jdKeywords.js` 的 `getJdKeywords(jdText, signal, override, jobTitle)`。
  - 命中缓存时 `hits + 1`、`updated_at` 刷新；未命中时写回 `keywords + job_title`。
- 表结构：`jd_keywords(hash PK, keywords, job_title, hits, created_at, updated_at)`。
- **不落 JD 原文、不落任何用户信息**，只有关键词与岗位名 → 公开无隐私风险。

## 聚合与清洗

`server/core/keywordLibrary.js`：

- `CATEGORIES`：岗位大类规则（前端 / 后端 / 移动端 / 算法数据 / 测试 / 运维云 / 硬件嵌入式 / 设计 / 运营市场 / 产品 / 销售客服 / 财务人事行政 / 其他），按 `job_title` 关键字匹配，**先匹配先胜出**。
- `cleanKeyword`：去首尾符号、去纯符号/纯数字、去过短（<2）、去过泛词（STOPWORDS）。
- `buildLibrary({ minJd, keywordLimit })`：按 JD 去重统计每个词出现在多少份 JD 中；返回
  `{ updatedAt, totalJds, totalKeywords, categories[], topKeywords[] }`。
  - **只统计有 `job_title` 的行**（历史无归属的旧行会被忽略，避免"其他"变垃圾筐）。

## 公开接口与页面

| 路径 | 说明 |
|------|------|
| `GET /api/keywords` | 公开 JSON（无鉴权），全量分类 + 高频词 |
| `GET /api/keywords/:slug` | 单个分类的 JSON |
| `GET /keywords` | **服务端渲染 HTML**（分类索引 + 全站高频词） |
| `GET /keywords/:slug` | 服务端渲染的岗位方向页 |
| `GET /robots.txt` | 允许 `/keywords`，屏蔽 `/api/`、`/admin`、`/share/`、`/history`、`/account` |
| `GET /sitemap.xml` | 列出 `/keywords` 与各分类页 |

> **为什么服务端渲染**：前端是 SPA（客户端渲染），搜索引擎难以索引。这些公开页由
> `server/seo/keywordPages.js` 直接输出完整 HTML（含 `<title>`、`meta description`、
> canonical、Open Graph、JSON-LD），并由 `server/index.js` 在静态兜底**之前**挂载。

## 冷启动保护（重要）

数据量小时，空壳/薄内容页对 SEO 与观感都是反效果，因此设了发布门槛（`server/core/keywordLibrary.js`）：

- 分类发布条件：`jdCount ≥ KEYWORDS_MIN_JD`（默认 5）**且** 关键词数 `≥ KEYWORDS_MIN_KEYWORDS`（默认 10）→ 标记 `publishable`。
- 全站可索引条件：JD 总数 `≥ KEYWORDS_MIN_TOTAL_JD`（默认 20）→ `siteReady`。

据此的行为：

| 状态 | `/keywords` | `/keywords/:slug` | sitemap |
|------|-------------|-------------------|---------|
| 全站未达标 | `noindex` + 「正在积累」+ CTA | `noindex` + 「正在积累」+ CTA | **不含** `/keywords` |
| 全站达标、分类未达标 | 只链**可发布**分类，其余标注"仍在积累" | `noindex` + 「正在积累」 | 不含该分类 |
| 达标 | `index` | `index` | 含 `/keywords` 与可发布分类 |

- 未达标页面**不进 sitemap、不被索引**，但保留 URL（展示「积累中」并引导去评估，把冷启动变成拉新）。
- 阈值可用环境变量覆盖：`KEYWORDS_MIN_JD` / `KEYWORDS_MIN_KEYWORDS` / `KEYWORDS_MIN_TOTAL_JD`。
- 测试：`server/__tests__/keywordPages.test.js`（三种状态下的 robots / 链接 / sitemap）。

## 环境变量

- `SITE_URL`：站点绝对地址（如 `https://example.com`），用于 canonical 与 sitemap 的绝对链接；未设置时输出相对路径。
- `KEYWORDS_MIN_JD` / `KEYWORDS_MIN_KEYWORDS` / `KEYWORDS_MIN_TOTAL_JD`：冷启动发布门槛（见上）。

## 前端入口

`src/components/Nav.tsx` 增加了一个**原生 `<a href="/keywords">`**（不能用 SPA `<Link>`，否则会被
React Router 的 `*` 兜底重定向回首页）。

## 注意

- 页面缓存 `Cache-Control: public, max-age=3600`。
- 数据量少时页面较薄，属正常；随评估量增长自然变厚。
- 新增/调整岗位大类只需改 `CATEGORIES`，页面与 sitemap 自动跟随。
