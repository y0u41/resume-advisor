# 游客转化实验

> 游客漏斗（试用 → 注册）已完全可度量。本功能用**按 IP 稳定分桶**跑 A/B 对照，
> 回答"试用给几次 / 预览给多长"这两个直接影响获客的问题——不靠拍脑袋。

## 实验设计

两个独立因素，各自 50/50 分桶（同一访客始终在同一组）：

| 因素 | 对照组 A | 实验组 B | 环境变量 |
|------|---------|---------|----------|
| 试用次数（次/天） | 3 | 5 | `GUEST_AB_LIMITS=3,5` |
| 预览长度（字） | 800 | 1500 | `GUEST_AB_PREVIEW=800,1500` |

- 未配置即**单组**（用 `GUEST_LIMIT` / `GUEST_PREVIEW_CHARS`），实验关闭。
- 分桶：`sha256(salt:ip)[0] % 2`，`salt` 分别为 `limit` / `preview`（两个因素独立）。
- 预览长度回答的关键问题：**用户是否在看到「逐条改法」这类高价值内容前就断了？**

## 归因

- `guest_trial` 事件带 `{ student, limit, preview }`（`server/routes/guest.js`）。
- `register_from_guest` 事件带 `{ limit, preview }`——注册时按**同一 IP** 再算一次分桶
  （`server/routes/auth.js`），因此能归属到组。
- 转化率 = `register_from_guest / guest_trial`，按组统计。

### 已知偏差（解读时必看）

- **归因依赖浏览器 `localStorage.guest_trialed` 标记**：换设备、清缓存、无痕模式后注册会**漏计**，
  分子偏小 → 转化率被**低估**（保守方向，可接受，但别把绝对值当真相）。
- **两因素独立分桶**：`limit` 与 `preview` 各自独立分桶，所以按 `limit` 分组时组内 `preview` 分布仍可能不均；
  样本小时两者的**交互效应会互相污染**，不要只看一个维度就归因。

## 样本量阈值

- `GUEST_AB_MIN_SAMPLE`（默认 **100**）：单组试用数低于它时，后台卡片顶部提示「样本量不足，仅供参考」，
  对应组的「样本」列标「不足」。
- 接口 `GET /api/admin/guest-experiment` 返回 `minSample`、`enoughSamples`、每组 `enough`。
- **单组 ≥ 100 次试用前，不要下"5 次更好"这类结论。**

## 查看

- 管理员 `GET /api/admin/guest-experiment?days=1|7|0`。
- 后台「游客转化实验」卡片：两张表（按试用次数 / 按预览长度），各显示 试用 / 注册 / 转化率。
- **样本少时波动大，建议每组 ≥ 100 试用再下结论。**

## 成本盯盘

免费档默认走 **GLM-Flash（单价 ¥0）**，理论上边际成本 ≈ 0；跑实验期间用
`GET /api/admin/usage?days=7` 看 `byModel` / `byFeature`，确认游客试用（`guest_evaluate`）
没有意外落到付费模型上。
